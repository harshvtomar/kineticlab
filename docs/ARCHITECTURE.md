# KineticLab Architecture — Stage 2 (v0.2.0)

## Source boundaries

- `src/domain`: read-only starter-scene metadata and validator. IDs are stable and remain identical to Stage 1.
- `src/features/simulation`: **unchanged Stage 1 Zustand store** holding paused/grid/resetEpoch only. Rapier, not Zustand, owns actual physics positions and collisions.
- `src/features/workspace`: **new Stage 2 UI-only state** (panels, catalog query/category/preview, selected object metadata, help, inspector mode) plus pure filters and shortcut parser.
- `src/components/scene/StarterPhysicsWorld.tsx`: unchanged Stage 1 React Three Fiber + Rapier demonstration. No components placed by UI yet.
- `src/components/layout`: HTML/React shell controls. Previews cannot manipulate 3D objects or change physical properties.
- `src/app`: high-level composition, desktop/mobile panel breakpoints, keyboard event handler. The editor `<main key="editor">` has a stable key so hiding/showing sibling panels does **not** remount the Canvas/Physics tree.

## Data flow

```text
[Toolbar / keyboard] ---> [Simulation Zustand store] ---> [Rapier paused, reset / grid]
                     |
                     +--> [Workspace Zustand store] ---> [Library filter/view state]
                                                  ---> [Inspector starter metadata]
                                                  ---> [Help dialog / responsive drawer state]

[Immutable starter fixture metadata] ---> [Rapier rigid bodies and 3D render]
                                   +--> [Inspector read-only object properties]
```

## Stable Scene 1 invariants

- `STARTER_OBJECTS` exactly four IDs: `ground-01`, `ramp-01`, `ball-01`, `stopper-01`.
- `PHYSICS_SETTINGS.gravity` = `[0, -9.81, 0]`.
- World reset remounts only when **Restart** increments `resetEpoch`; UI panel toggles do not deliberately change it.
- `@react-three/rapier` still owns dynamic motion.
- Model-editing operations are not available; selected object is UI metadata, not an active rigid-body handle.

## Responsive, accessibility & verification

- Desktop: CSS grid, independently collapsible panels.
- <=1070px: media-aware panel state closes on crossing breakpoint; panels become overlay drawers; backdrop closes the drawer.
- Native `<dialog>` for focus management and Esc close; form-safe keyboard shortcuts; visible keyboard focus and skip-to-content link.
- Breakpoint and visual checks require a real browser (pending Stage 2 Mac smoke verification).

## Stage 3 boundary

Add workspace grid/camera tools, orbit limits and viewport quality improvements, but do not implement object placement before Stage 6 or edit physical constants before Stage 19. Preserve Stage 1’s real physics and all Stage 2 UI behaviors.

## Stage 4 architecture (v0.4.0)

Stage 4 **continues** from corrected Stage 3 v0.3.1. Canonical `STARTER_SCENE` is generated by `migrateLegacyStarterScene(LEGACY_STARTER_OBJECTS)` and passed through `createMechanicalScene`. It is validated and deeply frozen. This canonical model has four typed discriminated descriptors and version 1 scene format.

```
legacy-fixtures.ts (Stage 3 positions and physics constants)
      |
      v
starter-scene.ts (kind-specific dimensions, appearance, physics -> migration)
      |
      v
registry.ts (validation, immutable clone, selectors, JSON IO)
      |--------------------------|
      v                          v
StarterPhysicsWorld.tsx      Inspector.tsx
      |
      v
Rapier fixed/dynamic bodies
```

`fixtures.ts` provides the original `STARTER_OBJECTS` facade derived from the canonical registry, maintaining compatibility with the existing `camera/views.ts` API and original unit tests. Legacy fixture data is **not** used directly to construct Rapier bodies or inspector contents. Registry snapshots are immutable; an editor with deliberate controlled mutation belongs in Stage 5–7. All body dimensions, materials, dynamics, transforms and collider shapes used by Rapier are descriptor-derived. Physics world gravity remains the preexisting global `PHYSICS_SETTINGS` constant.

Tests: `registry.test.ts`, `starter-scene.test.ts`, full historical test files, plus standalone strict-TS domain compile and registry verification (`npm run check:registry`).

## Stage 5 extension (v0.5.0)

Stage 5 preserves immutable schema v1 and its original migration. The in-memory active scene is `useSceneStore(state => state.scene)`; both the renderer and Inspector read the same snapshot. `scene-edit.ts` is a pure, ground-protecting removal policy. `features/scene/actions.ts` requires an explicit pending confirmation before calling the store, and only successful removal remounts Rapier. Selection and modal state belong to workspace UI store; they never modify the canonical Stage 4 `STARTER_SCENE` constant. Mesh selection uses emissive material only, not an additional collider. Reload resets the ephemeral in-memory scene. Stage 6 will add placement on top of this model.
